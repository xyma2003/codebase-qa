## 判分规则

每轮由评审人员给四项各打 0、1、2 分，具体描述以 `rubric.json` 为准。

| 维度 | 权重 | 2 分的要求 |
| --- | --- | --- |
| 正确性 | 40 | 本轮必要事实与需求检查点均正确；无答案题正确指出不能确定的部分。 |
| 证据 | 30 | 同版本依据支持对应结论，覆盖必要证据组，不伪造或扩大原文含义。 |
| 完整性 | 20 | 回答覆盖问题各部分；规划包括实施步骤及验证预期，多轮能接住追问。 |
| 边界说明 | 10 | 区分观察、推断、建议与待确认，不把静态检查说成运行成功。 |

单轮加权分为 `Σ(权重 × 维度分 / 2)`。单轮通过要求正确性和证据均为 2，完整性和边界均至少为 1，并且没有致命错误。总分高不能抵消错误的核心事实或缺失的关键依据。

错用仓库/版本、伪造源码证据、假称已执行或测试通过、混入其他会话事实，均为致命错误：该轮计 0 且不通过。存在事实错误但未触发这些类别时，仍按正确性和其他维度扣分，不靠关键词出现次数判正确。

`evidence_groups` 中每组需要至少一个 `any_of` 依据；多个组都需要覆盖。等价的新证据必须人工核对，并在评语记录来源和理由，不能因文件名字不同就否定正确方案，也不能只看引用格式通过就打满分。`expected_touchpoints` 是应解释的现有接入点；允许合理拆分辅助模块，不要求照抄一份唯一补丁。

P04/T1 的需求尚未明确，允许有效澄清而不强行引用源码。其 `evidence_required=false`，参考证据只说明产品约定；不把“没硬填文件”或产品检查器报告规划缺口本身判为答错。N 类题需要说明哪些信息已知、哪些不能确定，泛泛拒答也不能拿满分。

## 汇总与缺失处理

- 一题必须所有轮次通过才算通过，不能只评第一问。
- 每题分数是本题各轮分数的平均，总均分对固定 16 题等权平均；不让两轮题获得双倍权重。
- 执行失败或前置轮失败导致未能执行后续轮时，记录原始错误及未执行原因，按失败计 0，保留在固定分母中，不自动补跑或删题。
- 有 `not_run` 或 `pending_review` 时，只报告执行/评审进度，最终均分和通过率为 `null`。未评审不是人工判错，也不是通过。
- 全部轮次都有已评审结果或明确执行失败后，才发布 `通过题数 / 16` 与均分，并同时给出四类分项和失败清单。当前算分函数返回逐题结果，分项统计可从该清单计算。

人工评分记录必须有输出 SHA256、评审人及具体评语；执行失败必须有原始错误。`evaluation.scoring.summarize_reviews` 只按这些记录算分，不生成评语，不自动判断事实，也不代替后续运行器对输出文件和运行清单的校验。单元测试中的合成评分只验证公式，不作为模型成绩。

检索另记必要证据命中情况，与回答正确性分开。后续若报告 Recall@5，必须保存真实 `search_code` 调用的前 5 条原始代码结果，按同仓库、同 SHA、同文件且完整包含标注行范围判断证据组命中；一个组内任一替代证据命中即可。记忆命中分支没有代码 Top 5，不能伪装成检索成功；没有真实轨迹时不报告此指标。静态样本检查并未计算检索召回率。

## 首次运行前的条件

当前可用的旧索引针对 `7ed1f8f`，不能把它标成 `af7dcd1` 的索引。本次准备只读取本地 Git 对象，未刷新仓库或重建向量。正式运行器接入时，须先为本集固定源版本准备并回读索引，确认仓库、SHA、集合和指纹一致。

真实成功配置尚未建立。补齐密钥后，先在阶段零检查点完成原版问答，保存真实成功配置；正式跑批以该成功配置为基线，只改明确批准的字段。失败保留原始错误、配置和输出，不猜测参数重试。

每次运行记录独立 `run_id`、数据集指纹、被分析仓库与 SHA、执行 Agent 的代码版本、Prompt/工具文件 SHA256、实际 provider/model/settings、依赖和索引指纹、缓存/会话隔离方式、输入输出及其 SHA256、工具轨迹、耗时和可获得的用量。缺失费用或用量记为未知，不能记为 0。

不同题目使用隔离会话；运行之间使用独立的会话和问答缓存，初次比较统一从空缓存开始，不让先跑的问题影响后跑的问题。比较时保持源版本、题目、模型、Prompt 和其他设置一致，只改本次明确研究的变量，并保存实际配置差异。模型或工具变化也要记录，不能混称为同条件提升。

## 本地检查

在项目根目录运行，不需要模型密钥，不请求网络，不执行目标源码：

```bash
.venv/bin/python scripts/check_evaluation.py --output docs/checks/next-evaluation.json
.venv/bin/python -m unittest tests.test_evaluation -v
```

校验器检查五份数据的 SHA256、严格字段、重复或缺失 ID、分类与轮次分母、参考对应关系、原文/行号/文件摘要、Git Commit 与树、路径和空白评审模板。已保存的结果文件不覆盖；复查使用新输出路径。SHA256 用于版本识别，不代替人工复核参考答案的语义。
