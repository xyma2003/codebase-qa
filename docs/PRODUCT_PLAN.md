# Codebase Q&A 产品方案

版本：0.5。更新日期：2026-11-12。沿用已同意的产品定位，加入历史会话恢复与工具过程展示。

## 产品定位

帮助开发者接手陌生 GitHub 仓库，理解实现、追踪问题，并获得有源码依据的修改方案。关键结论能够回到具体代码版本、文件和行号。

核心用户是需要了解开源项目、接手现有代码或准备修改功能的开发者。首版以公开 GitHub 仓库和 Python 项目为主要验收范围；其他语言先提供文本检索。

## 核心任务

1. 了解项目：用途、目录职责、入口和主要模块。
2. 追踪实现：定位功能经过的文件、函数和配置。
3. 准备修改：说明涉及文件、修改理由、实施顺序和验证方法。

典型问题：我想让这个项目支持真正的多轮对话，需要修改哪些地方？

结果应包含当前实现、问题依据、修改位置和验证建议。证据不足的部分明确说明；静态分析不能证明的运行行为保留为待验证项。

## 第一版用户流程

输入仓库地址 → 导入代码快照 → 查看项目概览 → 围绕问题研究 → 核对源码 → 连续追问 → 获得修改方案。

| 功能 | 交付行为 |
| --- | --- |
| 仓库导入 | 导入默认分支，记录实际 Commit，并选择已索引版本；任意分支选择后续实现 |
| 项目概览 | 解释用途、目录、入口和主要模块，并给出依据 |
| 实现分析 | 根据问题跨文件查找，解释关键执行流程 |
| 修改规划 | 列出涉及文件、理由、顺序和验证建议 |
| 连续追问 | 保持正确的仓库、代码版本和对话上下文 |
| 源码核对 | 点击引用，查看对应版本的代码和上下文 |

首版交付分析报告和修改方案。生成补丁、执行目标仓库的测试，进入后续阶段。

评测属于开发验收流程：固定版本和问题 → 保存运行档案 → 独立填写评审 → 查看分类结果与失败项 → 用同一输入验证下一次改动。日常使用仍围绕仓库理解、追问和修改规划。

| 内容 | 当前状态 |

| 快照、定位、静态概览与原文引用 | 本地工具验收通过；静态检查不证明入口运行成功。 |
| 多轮问答与修改规划 | 本地模拟模型流程通过；真实指代理解和方案质量尚未验收。 |
| 固定评测与运行归档 | 已有 16 题、19 轮，支持独立回读；真实后端已接入，运行须先核对成功配置和固定版本的实际索引。真实效果待密钥后验证。 |
| 评审导入与评分报告 | 已支持独立评审记录、输出绑定、分类结果和失败项材料；本次展示为合成评分流程样例。 |
| 轻量评审界面 | 并排查看问题、完整追问上下文、回答和参考源码；逐轮填写评分，保存后继续，生成独立报告。 |
| 页面过程区 | 已展示实际源码工具的名称、参数、耗时和返回长度，随完整回答保存；模型内部推理不展示。 |
| 历史会话恢复 | 可选择当前仓库、Commit 和索引下的已保存会话，恢复问答、引用与已记录的工具事件；长对话压缩仍待后续。 |
| 真实端到端成功基线 | 仍待模型密钥；不能用模拟结果替代。 |

验收分别记录“运行完成”“引用位置核对”“内容评审”，不合成一个模糊的成功标记。原始回答和档案保持封存，评分修订独立保存。

## 界面原则

保留清晰的仓库工作区：仓库与版本、分析与对话、按需展开的源码。过程区展示实际搜索、读取和任务状态。使用简短、常见的文案，保持简洁；不随意增加背景色、宣传语或无关提醒。

## 质量标准

- 检索能找到问题所需的关键代码，而不仅是相似文字。
- 关键事实有可核对的证据，引用位置与结论支持程度分别评估。
- 修改方案覆盖必要文件，验证建议可以实际执行。
- 仓库没有答案时，不虚构实现。
- 记录任务成功情况、耗时、调用次数和可获得的用量信息。

固定评测覆盖项目理解、功能定位、修改影响和无答案问题。评测样本与模型配置在比较时保持一致；正确率目标在测得基线后确定。

## 实施阶段

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 0 | 复现当前版本，保存环境、配置和结果 | 真实完成仓库导入、索引及模型问答，留下成功记录 |
| 1 | 版本快照、按行读取、引用校验和仓库隔离 | 新旧版本均可定位，引用不混用 |
| 2 | 概览、跨文件分析、修改规划和连续追问 | 完成了解项目到获得修改方案的完整流程 |
| 3 | 固定评测，对比检索、上下文和历史答案策略 | 能说明提升、退化、成本与适用范围 |
| 4 | 限定任务的补丁生成与隔离测试 | 交付代码变更和真实验证结果 |

## 迭代规则

每次做一个可验收的小改动。阶段完成后更新已验收、下一步和待验证想法。新增想法记录问题、证据、成本及所属阶段；改变定位或明显扩大范围时先与用户确认。

候选扩展：Issue 辅助定位、Commit 或 PR 影响分析、补丁生成与测试。候选方向不自动进入当前范围。

## 本轮形成的想法与优先级

| 想法 | 问题与本次依据 | 收益、成本及安排 |
| --- | --- | --- |
| 失败项材料 | 总分不能解释错在哪里；现在已能绑定问题、完整多轮上下文、回答、源码与评语。 | 本次报告先提供这层材料，成本低；用于阶段 3 定位问题，不自动推断错误原因或执行重跑。 |
| 同条件版本对比 | 已保存数据集、源版本、输出和评审摘要，可以检查两次结果是否可比。 | 后续展示每题改善/退化和成本变化，成本中等；阶段 3 候选，先有真实成功配置及可比运行，不把不同设置混成提升。 |
| 轻量评审界面 | 直接编辑 JSONL 的核对与修订成本较高。 | 已实现页面填写和恢复记录，复用现有规则、导入与报告；本地样例验收见[检查记录](checks/20261112-review-ui.md)。真实模型效果待配密钥后验收。 |

近期优先补齐真实首条问答与固定样本的小规模验收，再依据失败项决定改检索、上下文还是 Prompt。真实质量尚未测得时，不急于增加 Agent 数量或进入自动补丁执行。公开自仓库开发集也不能代替后续跨仓库验证。
