# Codebase Q&A 技术方案

版本：0.10。更新日期：2026-11-12。对应[产品方案](PRODUCT_PLAN.md)。本轮逐项补充程序层安全边界。

## 当前基础

第 0 阶段代码起点为 `7ed1f8f22e3c1caf1c23b9ca976bf9e86a5feffb`。项目已有 Git 克隆、Python AST 分块、ChromaDB 向量检索、Pydantic AI 工具调用、历史问答保存、Streamlit 和 MCP 接口。

用户确认以前尚未成功运行，因此不存在可复用的真实成功配置。首次成功运行后，将完整有效配置及依赖版本冻结为基线。

## 总体结构

仓库快照 → 代码与符号索引 → 研究 Agent 调用工具 → 证据检查 → 分析报告与修改方案。

首版沿用现有框架，把仓库、索引、检索、研究及证据能力整理为独立服务，由 Streamlit 和 MCP 共用。后续独立 API 可以复用这些服务。

| 模块 | 设计 |
| --- | --- |
| 仓库管理 | 用规范仓库身份和 Commit SHA 标识快照，显式更新 |
| 代码解析 | 保留原有函数/类分块，无定义时回退窗口；全文 AST 定位与导入分析补充模块线索，分块重构待评测 |
| 检索 | 默认仍用原向量检索；字面/符号与固定 RRF 融合可显式选择，重排尚未实现 |
| Agent | 单主 Agent 按问题调用工具；页面与 Python 支持显式运行限制，本地评测保留逐轮超时和遇错停止 |
| 证据 | 绑定快照、文件、行号、引用文本及对应结论 |
| 持久化 | SQLite 保存版本发布与会话，文件目录保存运行、评审及报告，ChromaDB 保存向量 |
| 接入 | Streamlit、MCP 共用服务；后续按需要增加 API |

阶段 0 不提前实现这些重构，也不主动更换模型或嵌入模型。

## 仓库与索引

`security.sources` 在源码工具、快照和向量读写入口执行敏感文件与凭据策略；实际文件读取限制 1 MiB，复用现有扫描上限。新快照不物化被拦截内容，旧快照与旧向量在读取时重新检查，不需要删除已有数据或更换嵌入模型。安全策略不修改源码、引用位置或原分块代码。检查常见高置信凭据、私钥及已配置密钥，不承诺识别所有业务秘密或编码内容。完整范围见 [SECURITY.md](../SECURITY.md) 与[安全计划](SECURITY_PLAN.md)。

快照保存仓库地址、请求分支、实际 SHA、获取时间、文件清单和内容校验值。索引记录快照、解析器版本、嵌入模型和构建状态。新索引完成后再发布为可用状态，失败不覆盖已完成索引。

首个版本功能针对远端默认分支，支持重新选择已成功索引的 SHA；任意分支选择单独实施。快照由已提交 Git 对象生成，不混入未跟踪文件或工作区修改。源码目录与清单分开保存，避免索引自身元数据。构建使用独立向量集合，完整回读后由 SQLite 事务发布；旧任务完成不能覆盖已发布的新任务。

界面和 MCP 把快照、集合与 Commit 一起传入工具，历史问答使用同一仓库和 Commit 的命名空间。旧未版本化索引只有在文本、位置及嵌入配置均匹配时复用向量，旧集合不修改。

分块保留文件与符号范围，避免只保留函数而漏掉导入、模块配置和顶层执行。Python 类与方法的重叠需要可控。多语言解析后续评估 Tree-sitter；语法关系与运行时调用关系分别处理，不能静态确认的关系不标成事实。

## 工具与任务

跨文件定位首版共用 `get_file_dependencies`，按选定快照与明确的 `source_root` 建立 `.py` 文件及包初始化文件的名称映射。默认源目录为仓库根，不猜测 `sys.path`；`src` 布局由调用方明确指定。支持正向导入引用及反向候选引用，保留别名、相对层级、函数和条件上下文。结果是静态候选，不推断调用发生、导入成功或完整修改影响。

`from` 导入不追踪成员最终定义与重导出链；包属性与子模块都可能相关时保留多个候选。通配符不展开，识别到的 `__import__`、`importlib.import_module` 调用只标为动态线索。每个导入名称或动态调用记一条引用，按文件、源码位置稳定分页；未完全确定计数覆盖已检查引用，不只覆盖反向查询目标。源文件核对 SHA256，完整引用原文上限 1000 字符，超出时保留位置并标明原文不可用；后续按行读取和引用复核沿用原工具。

项目概览先提供可核对的静态事实，由 `get_repo_overview` 在页面、Agent 和 MCP 之间共用：目录计数、Python 顶层定义及导入、模块文档摘录、配置文件名、根 README 前 20 行。入口规则只识别顶层 `__name__ == "__main__"` 判断、`__main__.py` 和匹配导入别名的 Streamlit 页面配置调用，结果称为线索，不推断运行成功或完整执行链。目标代码只解析，不导入或执行；仓库文档作为材料处理，不作为操作指令。

概览读取时核对快照与文件 SHA256，从已核对字节生成有版本、路径和行号的原文证据。扫描沿用单文件 1 MiB、总源码 10 MiB、候选文件 2000 个的上限；列表最多返回 30 个目录、30 个配置文件、30 个 Python 模块及 20 条入口线索，每个模块最多列出 20 个顶层定义与 20 个导入。截断与跳过分别标记。页面按需生成并按版本保留结果；切换仓库或版本清除旧概览。Agent 获得这些位置后仍需 `read_file` 获取本次引用编号，再组织说明。

基础工具包括文件列表、关键词搜索、语义搜索、按行读取及符号定位。工具返回结构化证据标识，避免模型自行拼接未经检查的文件位置。

源码查找首版由 `find_code` 共用服务实现，直接扫描选定快照，不依赖向量分块。文本与路径使用字面子串匹配；Python 定义使用 AST，保留类、方法、异步函数和嵌套名称及真实行号，不推断运行时调用关系。按路径、行号稳定排序，使用 `offset` 与 `next_offset` 分页；查找预览不登记为引用，需再次按行读取核对。

源码读取与查找共用路径约束。查找核对快照身份和已读取文件的 SHA256，单文件上限 1 MiB、单次读取上限 10 MiB、候选文件上限 2000；返回资源上限状态及跳过文件原因，避免把未完整检查当作没有实现。只处理现有支持的扩展名，依赖及构建目录保持排除。Python 语法无法解析时不猜测定义，可用文本模式查看。

任务流程：识别问题与所需证据 → 搜索入口 → 读取与追踪 → 检查证据缺口 → 补充检索或说明限制 → 输出结论及修改方案。

记录实际工具调用、结果摘要、错误、用量和状态，不展示模型内部推理。原始材料中的指令作为代码仓库内容处理。读取路径限制在当前快照内部，并处理路径穿越和符号链接。

## 对话与历史问答

已实现框架原生消息传递。SQLite `conversations.sqlite3` 保存会话范围、版本号及已发出的引用序号，轮次表保存当前问题、`result.new_messages()` 和 `CheckedAnswer`。消息使用已安装 Pydantic AI 的 `ModelMessagesTypeAdapter` 序列化与回读，下一问通过 `Agent.run(message_history=...)` 接收完整历史，不把页面文本拼成提示词。每轮只追加新消息，保留工具调用及返回结果。

会话绑定规范仓库地址、完整 Commit 和索引集合，加载时必须同时匹配；不匹配在请求模型之前拒绝。页面保持当前编号，切换仓库、版本、集合或点击“新建对话”时清除编号和显示历史。侧栏只列出同范围、至少完成一轮的历史会话，重新打开页面后可选择恢复；坏记录拒绝读取并保留此前有效界面状态。Python 接口可提供已有编号继续对话，MCP 客户端自行管理其模型上下文。

原生消息、问题、已检查回答和引用序号在同一事务内提交。模型或工具失败不写入半轮消息，页面保留此前成功问答；写入失败不发布成功回答，也不自动重试。使用会话修订号比较，旧并发请求不能覆盖已完成的新轮次。读取不完整、损坏或未知格式的记录会报错，不静默清空对话。

每问仍使用独立证据表，但同一会话内工具发出的 `[S1]` 等编号连续递增，包括发出但最终未被回答采用的编号。历史消息中的编号不登记为当前证据，追问必须重新读取源码；复制旧编号会报告不可核对。编号与原文校验不等同于结论语义正确。

当前保留全部原生历史，不自动压缩或总结。显式 `RunPolicy.input_characters_limit` 在请求模型前核对问题与序列化历史字符数，超限拒绝，不截断；模型特定上下文窗口与压缩仍待后续验收。为避免把依赖上下文的“它在哪里”等问题作为独立答案复用，后续轮次不写入独立问答缓存；首轮沿用原质量评分、阈值和引用检查。

`agent.tracing` 在六个源码工具入口记录实际调用，返回状态区分正在执行、已返回和异常失败，耗时与返回字符数来自本次执行。`ask_stream(on_event=...)` 可接收同步展示回调；回调异常不改变源码工具结果。完成事件随 `CheckedAnswer.tool_events` 存入原会话轮次，原生模型消息及输入保持不变，无需新增数据库列。旧记录缺少该字段时读取为空，不推断未保存的耗时。模型或会话保存失败时仍不提交半轮问答，已发出的界面事件仅反映实际发生的工具动作。

历史答案仅作为辅助资料。复用前核对版本及证据，不以相似度、长度或出现文件路径作为答案正确性的证明。缓存与基于反馈的模型训练分别表述。

`agent.runtime.RunPolicy` 以严格类型接收每轮 SDK 请求数、成功工具调用数、响应报告总 Token、异步超时和输入字符限制；未传策略时不覆盖 SDK 限额或模型生成参数。显式策略通过 `UsageLimits` 和异步取消实现，失败沿用原子会话规则。SDK 请求数不包含其内部 HTTP 重试，Token 检查在响应后发生；超时不抢占阻塞同步代码，也不保证服务端取消收费，不能宣称严格费用封顶。

`CheckedAnswer.runtime` 保存成功轮次的策略、检索方式、缓存开关、SDK 用量与耗时；旧记录缺少字段时读取为空。页面展示实际记录并提供折叠设置，`ask` / `ask_stream` 可显式关闭缓存读写，固定评测默认关闭缓存不变。缓存质量规则暂不调整，待真实同条件评审再决定阈值或准入方式。

## 输出与证据

结果包含结论、实现说明、证据、修改建议及待确认项。结构化输出用 Pydantic 定义并校验。

修改规划通过 `mode="plan"` 使用同一个 Agent、模型和工具，在本次运行的 `output_type` 指定 `ToolOutput(ChangePlan, name="submit_change_plan", max_retries=0)`。普通问答仍返回字符串，原质量评分和阈值不变。规划格式不合法则结束本次请求，不自动重试；格式有效但证据或文件检查不通过时，保留规划并列出检查问题。

`ChangePlan` 包含目标、带引用的当前行为、文件动作与修改要点、按顺序排列的步骤、验证方法及预期结果、待确认项。动作只描述建议的修改、新增或删除。修改与删除必须命中当前快照的文件并引用本文件源码；新增必须提供当前源码依据，路径不能覆盖已有文件、目录或跳过的 Git 对象，也不能位于已有文件或跳过对象之下。文本字段去除首尾空白后，路径须为规范 POSIX 相对路径，拒绝绝对路径、驱动器、反斜线、`..`、Git 元数据和路径内的控制字符。

程序复用本轮证据检查器，检查旧/未知编号、引用原文与版本，再检查重复文件、步骤涉及未列出文件及遗漏文件。新增文件引用的接入理由、修改内容、顺序逻辑与测试覆盖是否正确，仍需语义评估。信息不足时允许空清单和待确认项，同时显示缺失项，不强行补造方案。

Markdown 由程序统一生成，模型的文字和文件名作为文本转义，源码链接来自已核对证据。验证命令使用独立代码块展示，不执行。`CheckedAnswer.plan` 保存结构化结果，旧回答缺少此字段时仍可读取。规划保留在原生会话和已检查回答中，切换问答与规划模式保留上下文；规划不进入独立问答缓存，也不使用原字符串质量评分来宣称方案正确。MCP 客户端自行组织其模型规划流程，现有工具接口不变。

程序核对引用所属快照、路径、有效行号和原文。结论是否得到证据支持，使用固定样本人工核对，后续可增加辅助评审，但不把位置校验当成语义正确。

首版引用使用每次问答独立的证据表。版本化 Agent 工具从快照读取完整行后分配 `[S1]` 等编号；多轮会话延续已发出序号，单次无会话调用仍从 `[S1]` 开始。回答返回时再次核对文件 SHA256、完整 Commit、行号和原文，并由程序生成链接。超长行的部分内容不分配完整行引用。围栏代码块和行内代码里的编号样例不作为引用处理。

`SourceCitation` 和 `CheckedAnswer` 用 Pydantic 定义，页面保存本次核对结果并提供原文展开。未知编号、无引用或失效引用不进入版本化问答缓存；原有质量评分和阈值不变。缓存答案仅作为辅助材料，不自动登记为本次源码证据。MCP 的 `verify_source_citation` 共用相同原文核对服务，外部客户端可提供范围和引用原文独立校验。引用语义评审、持久化运行记录及跨会话证据管理留在后续阶段。

## 第 0 阶段方法

1. 检出当前代码并记录 SHA，建立项目独立环境。
2. 原样安装 `requirements.txt`，记录实际解析的依赖版本。
3. 验证导入、界面启动、Git 克隆、解析、嵌入、持久化检索和工具。
4. 使用用户选择的模型接口完成真实问答，保存工具调用及回答。
5. 保存完整有效配置、输入、输出、耗时、错误和执行边界；密钥只记录是否设置。

用户在 2026-11-10 选择仓库已有的 SiliconFlow `Qwen/Qwen3-32B` 配置。密钥由用户填入被 Git 忽略的 `.env`，不进入日志、文档或提交。

保留原有 `all-MiniLM-L6-v2`、分块设置、Top K 和记忆阈值。新增的运行目录、测试输入和观测设置单独记录。运行失败先保存原始错误与有效配置，不猜测改参数重试。

第 0 阶段只有真实模型问答成功，才标记端到端完成。启动、静态检查或模拟模型通过，仅证明各自覆盖的范围。

## 评测与比较

按固定快照保存问题及必要证据，覆盖理解、定位、影响和无答案问题。分别统计检索命中、回答正确、证据支持、方案完整、无答案处理、耗时和费用。

比较时固定问题、代码快照、模型、Prompt 与其他设置，只改变本次研究的变量；保存完整配置和字段差异。依赖升级也作为独立变更验收。

固定开发集保存在 [`evals/codebase-qa-v1`](../evals/codebase-qa-v1/README.md)，源代码锁定在 `af7dcd191999f0e5deb58a0c1983c526631a2ba9`。16 题、19 轮分别保存原始输入、逐轮检查点、证据组、致命错误和空白人工评审模板。31 段证据记录完整文件 SHA256、行号和原文；校验器直接读本地 Git 对象，不信任脏工作区，也不更新已有索引。

`evaluation.dataset` 用严格 Pydantic 模型检查数据完整性与源码对应关系，`Bundle.model_inputs()` 排除分类、参考答案与评审信息。`evaluation.scoring` 只计算人工填写的四维 0/1/2 评分：正确性 40、证据 30、完整性 20、边界 10。每题所有轮次均通过才算通过；失败保留固定分母，未运行或未评审时不发布最终分数。澄清题显式声明不强制源码引用，位置检查与语义评审继续分开。

该集是公开单仓库开发样本，不是独立隐藏测试。真实模型后端已接入；检索层已按原问题单次 Top 5 检查位置覆盖，实际回答内容评审仍待验收。正式跑批前先建立阶段零真实成功配置，再固定设置并记录对照差异。

离线检索对照复用固定的 533 条向量，18 轮共 47 个证据组。补充模块行未改善命中；固定字面/符号查找与 RRF 融合使部分重叠从 1 组增加为 4 组，完整覆盖仍为 1 组。默认 `semantic` 不变，显式 `hybrid` 经 `RepoDeps` 供 Agent、MCP 和评测共用，评测档案记录策略差异。实验不调用聊天模型，候选原文逐条核对 Git；结论只针对候选位置覆盖，详见[模块实验](checks/20261112-retrieval-modules.md)及[融合实验](checks/20261112-retrieval-hybrid.md)。

本地运行器 `evaluation.runner` 按固定输入逐题、逐轮串行运行。`build_agent(model)` 复用原有 Prompt 和工具，仅显式传入本地 `FunctionModel`；`_run_answer` 增加仅供服务层使用的模型实例、会话目录和结果观察回调，公共问答默认行为不变。源码快照和会话存储增加显式目录参数，评测使用独立目录。`RepoDeps.source_only` 在本地环境禁止记忆读写及向量工具，集合字段只作会话占位，实际向量状态明确为未构建。

每轮先写准确输入，再调用 SDK。使用 `capture_run_messages` 保存失败时也能取得的原生消息，成功生成时另存 `new_messages`、原始结果及框架用量。记录模型实际接收的消息/指令/工具定义，参考标注不传给本地模型。成功输出与评审记录用 SHA256 绑定；失败保留原异常和堆栈，同题后续轮次阻塞，未开始的其他题保持未运行，不自动重试。

`evaluation.archive` 最后生成归档清单，并独立检查固定数据、文件摘要、轮次与会话、原生消息与工具轨迹、原始/结构化结果、评审绑定及固定 Git 证据。便携 ZIP 不含 SQLite 或源码工作状态，新进程可仅依靠归档和本地 Git 对象复核。本地模拟输出保持待评审，不产生模型正确率，实际 provider 用量与费用为空。完整运行说明见[评测运行与归档](../evaluation/README.md)。

评审层使用三份独立材料：封存源运行、可编辑评审包、导入后封存的评分报告。`evaluation.reviews` 将评审绑定到运行编号、归档 SHA256、数据集指纹、判分规则字节摘要和逐轮输出 SHA256。评审包提供完整多轮输入、回答、检查点和源码依据；不修改源档案，也不将参考材料送给模型。

导入允许只提交部分轮次，未提交项保留原状态；重复/未知题号、错输出、改规则或参考上下文均拒绝，失败、阻塞和未运行轮次不可人工改成完成输出。四维权重和固定题目不变，逐轮计算复用同一公式。只要还未完成必要评审，整体和分类的最终均分/通过率均为空；已知失败项仍可先查看。

`evaluation.reporting` 生成 JSON、Markdown、分类结果和失败项材料，记录评分实现摘要、原始导入文件及合并后的固定分母。失败材料包含同题上下文、输出、版本化引用、评语及评分项标记，不由程序猜测根因。独立校验器重新核对源档案和导入记录并重算报告，拒绝改分后仅重写摘要清单的情况。

评分来源显式区分 `simulation` 与人工声明记录。运行来源另分 `local_fixture`、`provider_fixture` 和 `siliconflow`；模拟输出和构造评分均不是线上模型成绩。运行完成、引用核对、内容评分三类状态分别保留，合成记录不能升级成真实模型成功基线。操作方法见[人工评审与报告](../evaluation/REVIEWING.md)。

`evaluation.real_preflight` 核对原版成功材料、原版代码摘要、配置与依赖；`evaluation.indexes` 从固定 Git 对象创建专用向量集合，不发布为页面当前索引，执行前回读全部原文、元数据和向量摘要。`evaluation.real_runner` 显式选择已确认的 SiliconFlow 模型，复用同一个运行器和生产工具，专用运行关闭缓存读写，普通问答默认行为不变。

`RecordedModel` 在 SDK 边界保存逐次消息、模型设置、工具与输出定义和实际响应，不改生成参数；响应自带用量独立归档，费用保持未知。SDK 原有内部重试值被记录，评测器不重跑失败轮次。新增版本 2 档案绑定基线、实际索引和响应，旧版本 1 模拟档案及旧报告仍可核对。来源为模拟传输时，不能声明实际请求了真实模型；完整人工评审前不发布最终成绩。

轻量界面由 `pages/1_评测评审.py` 接入现有 Streamlit 多页面侧栏，`evaluation.review_ui` 负责展示，`evaluation.review_workspace` 负责编辑与生成独立报告。打开或保存时沿用完整源档案和评审包校验，展示同题此前各轮问题、回答、实际引用、固定检查点及参考源码。原回答与文档作为普通文本，源码使用代码块及程序生成的版本化链接。

新评审包默认不填分数，只有完成输出的轮次可填写四维评分、致命错误、评审者与理由；空项拒绝保存。编辑使用本机文件锁、完整工作包修订摘要和临时文件原子替换，旧页面不能覆盖新评分。记录变更后须重新打开再继续，保存错误保留原记录。清除评分只把该轮恢复为待评审，输出绑定与已封存报告不变。

页面生成报告继续调用 `import_review`，每次使用新目录。下载 ZIP 先调用原独立校验器，沿用原九文件报告格式，可用原 CLI 回读；源运行仍单独保存。页面区分本地模拟、接口模拟和真实模型归档，自动化填写的评分明确保留 `simulation` 来源。未完成评审不显示最终均分或通过率，没有另建评分公式或从评审页面请求模型。

后续同条件对比应先核对数据集、被分析源版本、规则及运行配置，再给逐题变化；可比性失败时保留差异，不直接汇总“提升”。该项仍是候选，本次不扩展到真实模型批跑或自动代码执行。

## 后续实现顺序

GitHub Actions 由 uv 0.12.3 安装 macOS arm64 的 Python 3.12.13，在 macOS 15 上使用原依赖哈希锁，完整拉取 Git 历史后核对固定集、运行全量测试并独立回读已发布接口模拟归档。工作流读取仓库权限，Actions 固定到已核对的 Commit；聊天模型密钥为空、Hugging Face 离线，测试只使用本地模型、内存传输与临时向量库。检查文件写入 runner 临时目录并归档 14 天，不污染源码工作区。CI 通过表示工程流程检查，不代表真实模型准确率通过。

新增逐轮运行记录在归档回读时与实际请求、框架用量和运行策略交叉核对，旧档案没有该字段时保持兼容。评审页面按来源显示真实评测或样例指标，不把接口模拟当真实模型。架构与演示说明见 [ARCHITECTURE.md](ARCHITECTURE.md) 和 [DEMO.md](DEMO.md)。

版本与引用基础 → 完整研究流程 → 固定评测与优化 → 限定范围的代码修改和隔离执行。多 Agent、独立前端、图数据库或新的部署组件，依据具体瓶颈再决定。

用户要求先推送检查点并继续实施。因此，模型密钥待配置期间，可以先验收不调用聊天模型的第 1 阶段基础能力。原版真实问答仍须在保存的原代码检查点完成，不能用修改后的工具或 Prompt 替代。
