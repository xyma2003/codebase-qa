## 总体结构

仓库快照 → 代码与符号索引 → 研究 Agent 调用工具 → 证据检查 → 分析报告与修改方案。

首版沿用现有框架，把仓库、索引、检索、研究及证据能力整理为独立服务，由 Streamlit 和 MCP 共用。后续独立 API 可以复用这些服务。

| 模块 | 设计 |
| --- | --- |
| 仓库管理 | 用规范仓库身份和 Commit SHA 标识快照，显式更新 |
| 代码解析 | Python AST，补全模块级语句、导入与符号；其他语言先文本解析 |
| 检索 | 函数名、路径和关键词匹配结合向量检索，效果由固定问题集验证 |
| Agent | 单主 Agent 按问题检索、读取和追踪，限制循环、耗时与用量 |
| 证据 | 绑定快照、文件、行号、引用文本及对应结论 |
| 持久化 | SQLite 保存仓库、会话、运行和引用；ChromaDB 保存向量 |
| 接入 | Streamlit、MCP 共用服务；后续按需要增加 API |

阶段 0 不提前实现这些重构，也不主动更换模型或嵌入模型。

## 仓库与索引

快照保存仓库地址、请求分支、实际 SHA、获取时间、文件清单和内容校验值。索引记录快照、解析器版本、嵌入模型和构建状态。新索引完成后再发布为可用状态，失败不覆盖已完成索引。

首个版本功能针对远端默认分支，支持重新选择已成功索引的 SHA；任意分支选择单独实施。快照由已提交 Git 对象生成，不混入未跟踪文件或工作区修改。源码目录与清单分开保存，避免索引自身元数据。构建使用独立向量集合，完整回读后由 SQLite 事务发布；旧任务完成不能覆盖已发布的新任务。

界面和 MCP 把快照、集合与 Commit 一起传入工具，历史问答使用同一仓库和 Commit 的命名空间。旧未版本化索引只有在文本、位置及嵌入配置均匹配时复用向量，旧集合不修改。

分块保留文件与符号范围，避免只保留函数而漏掉导入、模块配置和顶层执行。Python 类与方法的重叠需要可控。多语言解析后续评估 Tree-sitter；语法关系与运行时调用关系分别处理，不能静态确认的关系不标成事实。

## 工具与任务

跨文件定位首版共用 `get_file_dependencies`，按选定快照与明确的 `source_root` 建立 `.py` 文件及包初始化文件的名称映射。默认源目录为仓库根，不猜测 `sys.path`；`src` 布局由调用方明确指定。支持正向导入引用及反向候选引用，保留别名、相对层级、函数和条件上下文。结果是静态候选，不推断调用发生、导入成功或完整修改影响。

`from` 导入不追踪成员最终定义与重导出链；包属性与子模块都可能相关时保留多个候选。通配符不展开，识别到的 `__import__`、`importlib.import_module` 调用只标为动态线索。每个导入名称或动态调用记一条引用，按文件、源码位置稳定分页；未完全确定计数覆盖已检查引用，不只覆盖反向查询目标。源文件核对 SHA256，完整引用原文上限 1000 字符，超出时保留位置并标明原文不可用；后续按行读取和引用复核沿用原工具。

项目概览先提供可核对的静态事实，由 `get_repo_overview` 在页面、Agent 和 MCP 之间共用：目录计数、Python 顶层定义及导入、模块文档摘录、配置文件名、根 README 前 20 行。入口规则只识别顶层 `__name__ == "__main__"` 判断、`__main__.py` 和匹配导入别名的 Streamlit 页面配置调用，结果称为线索，不推断运行成功或完整执行链。目标代码只解析，不导入或执行；仓库文档作为材料处理，不作为操作指令。

概览读取时核对快照与文件 SHA256，从已核对字节生成有版本、路径和行号的原文证据。扫描沿用单文件 1 MiB、总源码 10 MiB、候选文件 2000 个的上限；列表最多返回 30 个目录、30 个配置文件、30 个 Python 模块及 20 条入口线索，每个模块最多列出 20 个顶层定义与 20 个导入。截断与跳过分别标记。页面按需生成并按版本保留结果；切换仓库或版本清除旧概览。Agent 获得这些位置后仍需 `read_file` 获取本次引用编号，再组织说明。

基础工具包括文件列表、关键词搜索、语义搜索、按行读取及符号定位。工具返回结构化证据标识，避免模型自行拼接未经检查的文件位置。

源码查找首版由 `find_code` 共用服务实现，直接扫描选定快照，不依赖向量分块。文本与路径使用字面子串匹配；Python 定义使用 AST，保留类、方法、异步函数和嵌套名称及真实行号，不推断运行时调用关系。按路径、行号稳定排序，使用 `offset` 与 `next_offset` 分页；查找预览不登记为引用，需再次按行读取核对。

源码读取与查找共用路径约束。查找核对快照身份和已读取文件的 SHA256，单文件上限 1 MiB、单次读取上限 10 MiB、候选文件上限 2000；返回资源上限状态及跳过文件原因，避免把未完整检查当作没有实现。只处理现有支持的扩展名，依赖及构建目录保持排除。Python 语法无法解析时不猜测定义，可用文本模式查看。

任务流程：识别问题与所需证据 → 搜索入口 → 读取与追踪 → 检查证据缺口 → 补充检索或说明限制 → 输出结论及修改方案。

记录实际工具调用、结果摘要、错误、用量和状态，不展示模型内部推理。原始材料中的指令作为代码仓库内容处理。读取路径限制在当前快照内部，并处理路径穿越和符号链接。

## 对话与历史问答

已实现框架原生消息传递。SQLite `conversations.sqlite3` 保存会话范围、版本号及已发出的引用序号，轮次表保存当前问题、`result.new_messages()` 和 `CheckedAnswer`。消息使用已安装 Pydantic AI 的 `ModelMessagesTypeAdapter` 序列化与回读，下一问通过 `Agent.run(message_history=...)` 接收完整历史，不把页面文本拼成提示词。每轮只追加新消息，保留工具调用及返回结果。

会话绑定规范仓库地址、完整 Commit 和索引集合，加载时必须同时匹配；不匹配在请求模型之前拒绝。页面保持当前编号，切换仓库、版本、集合或点击“新建对话”时清除编号和显示历史。已保存轮次保留；历史会话列表和浏览器重新加载后的选择功能仍待实现。Python 接口可提供已有编号继续对话，MCP 客户端自行管理其模型上下文。

原生消息、问题、已检查回答和引用序号在同一事务内提交。模型或工具失败不写入半轮消息，页面保留此前成功问答；写入失败不发布成功回答，也不自动重试。使用会话修订号比较，旧并发请求不能覆盖已完成的新轮次。读取不完整、损坏或未知格式的记录会报错，不静默清空对话。

每问仍使用独立证据表，但同一会话内工具发出的 `[S1]` 等编号连续递增，包括发出但最终未被回答采用的编号。历史消息中的编号不登记为当前证据，追问必须重新读取源码；复制旧编号会报告不可核对。编号与原文校验不等同于结论语义正确。

当前保留全部原生历史，不自动压缩或总结。长对话的上下文预算、历史选择和压缩在后续单独验收。为避免把依赖上下文的“它在哪里”等问题作为独立答案复用，后续轮次不写入独立问答缓存；首轮沿用原质量评分、阈值和引用检查。

历史答案仅作为辅助资料。复用前核对版本及证据，不以相似度、长度或出现文件路径作为答案正确性的证明。缓存与基于反馈的模型训练分别表述。

## 输出与证据

结果包含结论、实现说明、证据、修改建议及待确认项。结构化输出用 Pydantic 定义并校验。

修改规划通过 `mode="plan"` 使用同一个 Agent、模型和工具，在本次运行的 `output_type` 指定 `ToolOutput(ChangePlan, name="submit_change_plan", max_retries=0)`。普通问答仍返回字符串，原质量评分和阈值不变。规划格式不合法则结束本次请求，不自动重试；格式有效但证据或文件检查不通过时，保留规划并列出检查问题。

`ChangePlan` 包含目标、带引用的当前行为、文件动作与修改要点、按顺序排列的步骤、验证方法及预期结果、待确认项。动作只描述建议的修改、新增或删除。修改与删除必须命中当前快照的文件并引用本文件源码；新增必须提供当前源码依据，路径不能覆盖已有文件、目录或跳过的 Git 对象，也不能位于已有文件或跳过对象之下。文本字段去除首尾空白后，路径须为规范 POSIX 相对路径，拒绝绝对路径、驱动器、反斜线、`..`、Git 元数据和路径内的控制字符。

程序复用本轮证据检查器，检查旧/未知编号、引用原文与版本，再检查重复文件、步骤涉及未列出文件及遗漏文件。新增文件引用的接入理由、修改内容、顺序逻辑与测试覆盖是否正确，仍需语义评估。信息不足时允许空清单和待确认项，同时显示缺失项，不强行补造方案。

Markdown 由程序统一生成，模型的文字和文件名作为文本转义，源码链接来自已核对证据。验证命令使用独立代码块展示，不执行。`CheckedAnswer.plan` 保存结构化结果，旧回答缺少此字段时仍可读取。规划保留在原生会话和已检查回答中，切换问答与规划模式保留上下文；规划不进入独立问答缓存，也不使用原字符串质量评分来宣称方案正确。MCP 客户端自行组织其模型规划流程，现有工具接口不变。

程序核对引用所属快照、路径、有效行号和原文。结论是否得到证据支持，使用固定样本人工核对，后续可增加辅助评审，但不把位置校验当成语义正确。

首版引用使用每次问答独立的证据表。版本化 Agent 工具从快照读取完整行后分配 `[S1]` 等编号；多轮会话延续已发出序号，单次无会话调用仍从 `[S1]` 开始。回答返回时再次核对文件 SHA256、完整 Commit、行号和原文，并由程序生成链接。超长行的部分内容不分配完整行引用。围栏代码块和行内代码里的编号样例不作为引用处理。

`SourceCitation` 和 `CheckedAnswer` 用 Pydantic 定义，页面保存本次核对结果并提供原文展开。未知编号、无引用或失效引用不进入版本化问答缓存；原有质量评分和阈值不变。缓存答案仅作为辅助材料，不自动登记为本次源码证据。MCP 的 `verify_source_citation` 共用相同原文核对服务，外部客户端可提供范围和引用原文独立校验。引用语义评审、持久化运行记录及跨会话证据管理留在后续阶段。

## 第 0 阶段方法

1. 检出当前代码并记录 SHA，建立项目独立环境。
2. 原样安装 `requirements.txt`，记录实际解析的依赖版本。
3. 验证导入、界面启动、Git 克隆、解析、嵌入、持久化检索和工具。
4. 使用用户选择的模型接口完成真实问答，保存工具调用及回答。
5. 保存完整有效配置、输入、输出、耗时、错误和执行边界；密钥只记录是否设置。

用户在 2026-11-10 选择仓库已有的 SiliconFlow `Qwen/Qwen3-32B` 配置。密钥由用户填入被 Git 忽略的 `.env`，不进入日志、文档或提交。

保留原有 `all-MiniLM-L6-v2`、分块设置、Top K 和记忆阈值。新增的运行目录、测试输入和观测设置单独记录。运行失败先保存原始错误与有效配置，不猜测改参数重试。

第 0 阶段只有真实模型问答成功，才标记端到端完成。启动、静态检查或模拟模型通过，仅证明各自覆盖的范围。

## 评测与比较

按固定快照保存问题及必要证据，覆盖理解、定位、影响和无答案问题。分别统计检索命中、回答正确、证据支持、方案完整、无答案处理、耗时和费用。

比较时固定问题、代码快照、模型、Prompt 与其他设置，只改变本次研究的变量；保存完整配置和字段差异。依赖升级也作为独立变更验收。
