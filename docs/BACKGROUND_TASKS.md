# 后台任务、并发与配额

网页的问答、修改规划、仓库导入与刷新通过同一服务端队列执行。页面短暂等待 0.2 秒，较慢的任务继续在后台运行。侧栏“任务”显示自己的最近 50 项记录，支持取消和打开结果。页面刷新、断开或切换页面不会重新提交任务；重新登录后可打开本人已完成的结果。

## 默认限制

| 项目 | 默认值 |
| --- | --- |
| 同时运行的问答 / 导入 | 全局 2 / 1 |
| 单用户同时运行 | 1 项，两种类型合计 |
| 排队数 | 全局 20 项，每用户 2 项 |
| 每用户每日问答 / 导入 | 20 / 5 项 |
| 全局每日问答 / 导入 | 100 / 20 项 |
| 问答运行限制 | 沿用 50 次模型请求、50 次工具调用、300 秒；用户只能收紧 |
| 导入总时限 | 600 秒后请求停止；同步工作返回后才释放槽位 |
| 单任务输入 / 结果 | 1 MiB / 4 MiB |
| 任务详情保留 | 7 天、最多 1000 条、逻辑数据预算 128 MiB |

次数按 UTC 自然日统计，包含已接单的失败和取消任务，不返还额度。同一提交编号加同一输入只接单一次；复用编号但改变输入会拒绝。同一会话只能有一个未完成任务，同一仓库的导入串行。队列满或预算不足会拒绝新任务，现有会话、缓存和索引不删除。

管理员可从 `.streamlit/tasks.toml.example` 复制为 `.streamlit/tasks.toml` 后调整并重启服务。该实际文件不进 Git；也可通过服务进程环境变量 `CODEBASE_QA_TASK_LIMITS_FILE` 指定配置路径。未知字段、错误类型和无效文件会拒绝启动队列，不退回宽松设置。页面和模型不能设置这些限额。没有实际配置时使用上表默认值。

任务次数上限不是 API 请求次数上限：一次问答可能发出多次模型请求。Token 仍由 SDK 在响应后检查，不能当作费用硬上限。入口网络限流、主机 CPU/内存/磁盘硬限制、共享公开索引的总磁盘治理属于下一阶段部署工作。

## 身份与状态

任务输入只允许固定类型及字段，不接受用户编号、角色、函数、命令、服务器源码路径。问答重新按仓库、Commit、索引和会话归属取回源码根目录，排队后对话已变化则拒绝执行。后台传播提交时的可信身份，并在启动、异步等待、工具进度和最终写入处检查有效期、邀请名单及取消。读取、列出和取消也检查归属，管理员不能越权读取其他用户任务。

独立自动刷新的状态区也重新认证，不依赖整页上一次的登录检查。退出不会自动取消已接单任务；任务保持私有，可在有效登录后恢复查看。过期或撤销身份不能保存新的私有结果。

状态包括排队、执行、正在取消、完成、失败、取消和中断。问答取消会等待异步模型清理完成。导入中的同步 Git/嵌入工作无法在任意位置强制结束，先显示“正在取消”，到达检查点停止；发布新索引前检查一次，失败只清理本次未发布集合，保留旧就绪索引。已保存结果之后不再接受取消。服务商已收到的请求不保证立即停止或退费。

## 持久化与重启

状态、规范输入、进度、脱敏错误和结果保存于 `.baseline_runtime/tasks/tasks.sqlite3`，文件权限为 `600`。后台只保存当前进程内的身份对象，不序列化登录令牌。该目录含私有问题与回答，须纳入后续备份及访问控制范围。

新进程持有 `worker.lock` 独占锁后才能启动队列。第二个服务进程使用同一目录会拒绝访问队列；当前不是跨机器任务系统。服务重启后，旧的排队、运行、取消中任务均标为“已中断”，不会自动恢复身份或重发模型请求。成功结果继续保留；极端中断可能发生在会话/索引已写入、任务状态尚未写入之间，应先查看历史与已索引版本，程序不自动重试。

过期的终态详情在下一次接单时清理，当前 UTC 日的记录仍参与计数；清理不删除会话历史。存储预算计算输入、结果、每条记录开销和未完成结果预留，不是 SQLite 文件或整个数据盘的物理硬配额。

可信本机 CLI、stdio MCP、固定评测入口保持原行为，不通过网页队列扣次数。不要把这些入口作为公网代理。单机进程的管理员本来可以执行 Python，属于可信主机边界。

## 检查与回滚

`tests/test_tasks.py` 覆盖实际临时 SQLite、竞争接单、双用户归属、并发、UTC 换日、重启、进程锁、取消清理和配额。真实 SDK 使用本地 FunctionModel；导入测试使用真实临时 Git 快照和模拟向量集合，不请求模型或远端仓库。页面使用 AppTest 检查后台等待、刷新、取消和恢复结果。

回滚前停止服务并备份任务数据库、会话和索引。旧版本 `8525d95` 不读取新任务库，已有终态记录会保留；不要同时启动新旧进程。重新升级后，未完成记录按重启规则中断，不能自动续跑。用户归属规则仍需保留，不能回滚至不理解多用户数据的早期版本直接接管数据。

实现依据：[Streamlit fragment 的独立刷新](https://docs.streamlit.io/develop/api-reference/execution-flow/st.fragment)、[Python 跨线程提交及取消](https://docs.python.org/3.12/library/asyncio-task.html#asyncio.run_coroutine_threadsafe)、[SQLite 事务](https://www.sqlite.org/lang_transaction.html)。真实模型、真实登录回调和公网负载验收仍待后续。
