# 登录与用户隔离验收

日期：2026-11-13。先更新产品和技术方案，再按已确认顺序实施登录、用户隔离及管理权限。聊天模型、嵌入、默认检索和固定开发集不变；没有调用真实身份服务商或聊天模型，没有升级包。

## 实现

- 默认网页通过 Streamlit OIDC 获取身份，按 issuer/sub、服务端受邀名单及时间字段授权。未知、过期、尚未生效或未登录身份不能进入业务页。角色不取自邮箱、页面状态或模型输出。
- 默认无配置即拒绝业务访问。独立本地启动命令只绑定回环地址，旧 CLI/MCP 继续属于可信本机操作员。
- ContextVar 传递身份，私有服务访问时重查过期与受邀名单；两个并发模拟模型任务不串上下文。撤销正在运行的用户后，模型返回也不能保存结果。
- 会话增加 owner_id 并在列表、读取及条件写入处检查。旧本地数据保留 local，不自动分给登录用户。公开源码索引共享，私有历史不共享。
- 历史答案按用户分集合，内容绑定增加所有者；列表、复用、批准、撤销及统计拒绝其他所有者数据。管理员不会自动读取其他用户的会话和缓存。
- 所有页面都检查身份；评测管理同时在服务入口检查管理员角色。在线评审只选择本地 CLI 登记且属于自己的运行，评审包、报告与下载限制在自己的工作目录。原本地操作员保留目录入口。
- 退出/换号清空私有页面状态。缓存批准回调重新认证，避免 Streamlit 回调先于页面正文执行时复用旧身份。

## 结果

新增 **24 项**测试，使用真实临时 SQLite/Chroma、真实 SDK FunctionModel 和 Streamlit AppTest。覆盖受邀名单、issuer、角色伪造、过期/nbf、撤销、默认拒绝、页面直达、换号退出、回调、用户间猜测 ID/伪造对象、缓存重放、管理员评审和下载，以及旧 SQLite 格式迁移。

最终全量 **324 项通过，121.015 秒**，未设置全局本地模式开关，各旧本地 UI 测试显式选择本地模式，认证测试使用假身份与临时配置。见[全量日志](20261113-user-access-unittest.log)、[机器摘要](20261113-user-access.json)和[专项日志](20261113-user-access-targeted.log)。

专项日志是前 23 项通过的记录；提交前新增登录客户端/Cookie 密钥纳入传递拒绝与脱敏规则的第 24 项，最终全量 324 项包含这项检查。初次全量 323 项日志同样保留在本机，没有用重复运行来伪造新增覆盖。

真实浏览器检查：默认网页和直接打开的评测页都拒绝未配置身份，不显示业务输入或服务器目录；显式本地启动后，原仓库和旧会话可以恢复。截图：[默认拒绝](20261113-auth-default-browser.png)、[本地旧会话](20261113-auth-local-browser.png)。这不代表真实 OIDC 登录已经成功。

原 2 个本地会话、3 个轮次的消息、问题与回答摘要在迁移前后完全一致：`9fd14008178680c699d441cd6e83dd0056b35b1f4c0faf206df92afec7de647f`；只新增所有者 local。原活动索引保留 58 个分块，未重建。真实 MCP stdio 9 工具/14 次调用通过，见[记录](20261113-user-access-mcp.json)。

Python 仍为 3.12.13，194 个依赖兼容；Authlib 1.9.5 原已安装和锁定，仅补为直接依赖。`.env` 没有修改，实际登录配置未创建；模板和配置说明已保存，实际配置被 Git 忽略。工作流经 actionlint 检查，新增测试自动进入原 CI。

最初认证专项中发现清空匿名页面状态会丢掉“登录”按钮事件，已修复为保留两个认证按钮状态，同时清除私有页面状态。另一个失败是 macOS `/var` 与 `/private/var` 的路径别名比较，修正测试为比较实际路径。原日志保留在本机 `.baseline_runtime/user-access-targeted-first.log` 和 `user-access-targeted-fixed.log`，不修改成成功记录。

## 留待密钥及后续阶段
