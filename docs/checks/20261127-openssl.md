## 首次 Linux 失败与定向修正

`41a6ca0` 的 [CI 45961679428](https://github.com/xyma2003/codebase-qa/actions/runs/45961679428) Mac 成功，458 项 / 141.765 秒；Linux 在 `dpkg-buildpackage -B -us -uc` 的 900 秒总上限退出。最后原始输出为 `dh_strip -a`，并非编译或用例断言失败。按未设置 nocheck 的 Debian 规则，进入打包说明测试阶段已返回成功；但 BuildKit 提示 `log limit 2MiB reached`，具体 TAP 总数与新增 QUIC 用例未完整取到，因此不认定本轮完成验收。原始 job 日志已下载保留。

只将本地构建程序的时限从 900 秒改为 1200 秒，并将 Linux 作业预算从 25 分钟调整到 35 分钟以覆盖后续对照和扫描；Mac 作业预算不变。源码、补丁、parallel=2、noudeb、Debian 构建规则、测试及其他配置不变。失败输出末尾补充原始诊断尾部、TAP 总结和完整日志摘要，避免关键证据被 BuildKit 裁切。8 项定向检查通过，包含新增的失败日志保留反向测试；实际 Linux 结果继续验收。

## 构建后源码状态修正

`5e50f56` 的 [CI 45963990355](https://github.com/xyma2003/codebase-qa/actions/runs/45963990355) Mac 成功，459 项 / 133.413 秒。Linux 完成完整 `dpkg-buildpackage`，程序确认原生日志 `Result: PASS`；但随后单独 `make test TESTS=test_quic_radix` 因 `Detected changed: ../Configure ../Configurations/10-main.conf ../Configurations/20-debian.conf` 重配退出，提示 `Please run the same make command again`，没有执行后置用例。原始诊断已下载，未按提示盲目重跑。

根因是 dpkg-source 构建后自动撤销补丁，再应用时改动配置文件时间戳。按[官方 dpkg-source 文档](https://manpages.debian.org/trixie/dpkg-dev/dpkg-source.1.en.html)，仅在构建目录的 `debian/source/local-options` 固定 `no-unapply-patches`，让相同补丁源码保留至后置回归；不改 Configure、编译参数、测试或 make 断言。构建前后除五份补丁相关文件外，再核对三个配置输入摘要。仍执行原定的独立 QUIC 回归和 GC 对照。

复核还发现原安装检查把二进制包 `Source` 当作必填；[Debian Policy 5.6.1](https://www.debian.org/doc/debian-policy/ch-controlfields.html#source)明确，同名同版二进制可省略该字段。修正为省略时取实际二进制包名，因此仅 openssl 可合法省略；libssl3t64 缺来源或 openssl 指向其他来源仍拒绝安装。新增正反例后 9 项定向通过；源码、包版本、时限与其他配置保持。
