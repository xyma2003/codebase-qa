本轮基线为最近真实成功的 `4dc149d69a26d9d5e3954a1cbcb1342567a4275f`、[CI 45581028837](https://github.com/xyma2003/codebase-qa/actions/runs/45581028837)。Linux 基线产物 SHA256 为 `68e8d883226e32398ddae18ae06520bfd6a3dc0dccecbdb5f5ab8318284e0109`，已下载校验。基线 451 项项目回归、Expat 双 C 扩展、数据迁移恢复通过，完整系统扫描为 342 条 / 179 编号 / 22 个不同 High，公开发布被阻断。

## 修复范围与来源

[11 月 17 日](https://openssl-library.org/news/secadv/20261117.txt)与[11 月 24 日](https://openssl-library.org/news/secadv/20261124.txt)官方公告公布了补丁；3.5.10 正式版本计划 12 月 1 日发布。[Debian 当前 3.5.9](https://security-tracker.debian.org/tracker/source-package/openssl)仍未标记这两个目标已修复。本轮使用现有 Debian 3.5.9-1~deb13u1 源码，回补同一 3.5 分支的官方提交，避免切换整套未发布源码。

| 目标 | 官方提交 | 回归要求 |

| CVE-2026-124709：终态接收流未及时回收 | `f3acb0a3328046741479482c51cec815839e1b05` | 使用真实 stream-map 源码；相同原生驱动分别编译补丁前后实现。原版必须复现 RESET_RECVD 无法回收，补丁后九种状态全部通过 |

四个 Debian 源文件的大小、SHA256 以及三个补丁的完整 SHA256 固定在 `deploy/openssl-update.json`。源码提取强制有效 Debian 签名和强校验和，补丁校验 SHA256 与提交身份。签名、补丁应用、完整原生构建、QUIC 与 GC 对照日志均归档。

保留原 Debian 编译规则及测试，不设置 nocheck、不修改失败用例。固定 `DEB_BUILD_OPTIONS=parallel=2`、`DEB_BUILD_PROFILES=noudeb`；编译器与开发包只留在构建阶段。三个运行包从 `3.5.9-1~deb13u1` 更新到本地版本 `3.5.9-1~deb13u1+codebaseqa1`，明确区别于 Debian 官方发布。

安装前后要求包状态完整、严格 `dpkg --verify` 通过，并且只有 `libssl3t64`、`openssl`、`openssl-provider-legacy` 三个版本变化。固定 Python 底座、Mac/Linux 锁、解释器、Expat、模型及其他系统包。构建报告绑定三个包和 libssl、libcrypto、legacy provider、CLI 四个实际文件摘要；安装和运行再次验证。

运行探针通过 `/proc/self/maps` 确认 Python 实际加载这些库，真实本机 TLS 往返要求可信证书通过、错误域名和不可信证书均拒绝。已有代理 TLS/WebSocket、限流、CPU 原生依赖、Expat C、数据迁移与恢复检查继续执行。cryptography 独立内置 OpenSSL 版本另记，本轮不宣称它或代理镜像中的副本已修复。
