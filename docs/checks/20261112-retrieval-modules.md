# 模块补充分块的离线检索对照

日期：2026-11-12。问题：函数和类之外的导入、常量与顶层代码未进入部分 Python 文件的向量分块，补充这些内容能否改善检索？

## 固定条件

复用上次成功回读的 `af7dcd1` 专用索引，原有 533 条向量不重新计算。问题、源码、嵌入模型、Top 5 和所有默认参数不变，只增加未被原函数/类分块覆盖的 Python 模块行。候选集合独立保存，没有发布到问答页面，也没有替换原始分块实现。

固定集 19 轮中，18 轮要求源码依据，共 47 个必要证据组；纯澄清轮次不计入检索分母。一个组可以满足任一参考证据。分别计算候选行范围与标注的部分重叠，以及若干候选联合完整覆盖标注范围的比例。

## 结果

| 指标 | 原索引 | 模块补充分块 |
| --- | --- | --- |
| 部分重叠的证据组 | 1/47 | 1/47 |
| 完整覆盖的证据组 | 1/47 | 1/47 |
| 对应比例 | 2.13% | 2.13% |
| 真实聊天模型请求 | 0 | 0 |

本次增补没有改善直接向量检索，因此不切换默认分块。下一步独立检查符号、路径与向量的融合召回；不能凭这一次结果就确定原因或更换模型。

这些数值测的是“把当前轮原问题直接做一次向量检索”的候选位置覆盖，不是完整 Agent 多步查找后的结果，更不是回答正确率。公开自仓库标注也不是独立隐藏测试；耗时仅保存本次记录，不作性能结论。

## 核对与复用

候选索引重建触发 ChromaDB 的余弦归一化，533 条旧向量中 48 条出现浮点微差，最大绝对差 `1.4901161193847656e-08`。原始逐字节校验失败的日志保留在本地；之后按 float32 机器精度检查并复用已建候选集合，未重算旧向量或重新构建候选。容差、实测误差、代码摘要、全部问题与候选位置保存在[结果 JSON](20261112-retrieval-modules.json)。

所有命中原文均逐条对照固定 Git 对象，覆盖率从固定标注重新计算后一致。公开记录保留位置与内容摘要，完整原文在固定 Git 版本和本地原始对照中可查。

全量 235 项测试通过，80.776 秒，见[测试记录](20261112-retrieval-modules-unittest.log)。新增检查包括模块缺口、原分块不变、真实临时向量对照、已有向量复用、候选复用、损坏索引拒绝、区间完整覆盖和澄清轮次分母。
