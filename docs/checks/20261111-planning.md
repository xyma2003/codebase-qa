# 修改规划验收

日期：2026-11-11。结果：本功能本地验收通过，未调用真实聊天模型。

## 功能行为

页面“任务”可选择“问答”或“修改规划”。规划模式使用原有 Agent、模型与源码工具，返回 `ChangePlan`：修改目标、带引用的当前实现、涉及文件及动作、具体修改点、实施顺序、验证方法与预期结果、待确认项。两种模式在同一会话内切换，保留原生上下文。

规划通过 Pydantic AI 的结构化输出工具 `submit_change_plan` 交付，格式错误直接报错，不自动重试。格式有效但缺少依据或存在路径、步骤问题时，回答中显示“规划检查”，同时保留结构化数据。信息不足可以不列修改文件，通过待确认项说明缺口。

| 程序检查 | 范围 |
| --- | --- |
| 引用 | 只能使用本轮读取发出的编号，核对完整 Commit、文件 SHA256、行号和原文。旧编号或未知编号不会借用当前证据。 |
| 已有文件 | 修改、删除的文件必须在当前快照中，并引用该文件自身的已核对源码。 |
| 新增文件 | 必须提供当前源码作为接入依据；路径不能与已有文件、目录或跳过对象冲突，不能穿过已有文件或跳过对象。 |
| 路径 | 字段去除首尾空白后，检查仓库相对的规范 POSIX 路径；拒绝绝对路径、驱动器、反斜线、`..`、Git 元数据、路径内的控制字符及路径别名。 |
| 步骤 | 报告重复文件、步骤中未列入修改清单的文件，以及未被任何步骤覆盖的修改文件。 |
| 展示与保存 | 文字与路径由程序转义，引用链接由程序生成；命令只作为代码块展示。结构化规划随会话原子保存，旧的无规划回答可继续读取。 |

这些检查不证明修改理由、方案内容、步骤逻辑或测试覆盖正确。规划不会修改目标文件或执行命令，验证字段按方法和预期结果展示，不据此登记已运行的验收结论；结构化规划不写入独立问答缓存。
