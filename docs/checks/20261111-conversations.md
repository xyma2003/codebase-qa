# 多轮对话验收

日期：2026-11-11。结果：本功能本地验收通过，真实聊天模型尚未调用。

## 本次行为

第二个问题通过 Pydantic AI 的 `message_history` 收到前面的问题、原始回答、工具调用和工具结果。每轮只保存 `result.new_messages()`，使用框架自带的 `ModelMessagesTypeAdapter` 做 JSON 序列化与回读；不会每轮重复追加全部历史，也不把页面文本拼接成提示词。

SQLite `chroma_db/conversations.sqlite3` 保存会话及完整轮次，同时保存已核对的回答和引用。会话绑定规范仓库地址、完整 Commit 和索引集合，范围不一致时在请求模型之前拒绝。页面保持当前会话编号；切换仓库、版本、集合或点击“新建对话”会开始独立上下文。

每轮问题、原生消息、已核对回答和引用序号一次提交。模型失败、工具后续失败、数据库写入失败或并发版本冲突，不覆盖已完成历史，不自动重试，也不发布写入失败的回答。读取不完整、损坏或未知格式的记录会报错。

同一会话内，工具发出的 `[S1]`、`[S2]` 等编号继续递增，包括发出但未被最终回答采用的编号。每问仍使用独立证据表，追问重新读取源码后才能引用；旧编号不会自动成为本轮证据。位置核对不能替代结论语义评估。

追问依赖历史上下文，因此不写入按单个问题检索的独立问答缓存；首轮沿用既有质量评分、阈值和引用检查。页面只有完整成功的问答进入显示历史，失败时保留此前问答。

## 配置与范围

代码起点为 `357738b8b7ebbaa4a3d73409caf061d47ea38eea`。SiliconFlow `Qwen/Qwen3-32B`、接口地址、依赖、嵌入模型、向量分块、检索参数及质量阈值保持原值。引用指令新增“历史消息只作背景，引用需重新读取”的要求。

本地 `FunctionModel` 证明原生历史确实传入、工具和保存流程正确，不证明真实模型能够正确理解指代。真实模型的回答效果、费用与长对话上限仍待密钥后验证。

本版保留完整原生历史，尚未压缩上下文，也未提供历史会话列表或浏览器重新加载后的会话选择。Python 调用方可通过已有 `conversation_id` 继续会话；MCP 客户端自行管理模型上下文。原版成功基线仍待配置密钥后在阶段零检查点单独建立。
